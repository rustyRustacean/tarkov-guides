# Shared Lib

Ported/adapted business logic reused across features.

**What's here:**

- `tarkov-api/` - the live tarkov.dev GraphQL data layer. `constants.ts` holds the endpoint URL and the `TARKOV_GQL_QUERY` text, ported **verbatim** from `old/TarkovTrackerWB-main/src/lib/refreshData.js`'s `GQL_QUERY` (the only GraphQL query in either legacy repo - `old/tarkov-tips` has none of its own). `types.ts` hand-writes the wire/normalized TypeScript shapes (no `graphql-code-generator` - one query with a well-known field set is small enough to fully own; revisit if the query's surface grows significantly). `fetch-tarkov-data.ts` does the actual POST + error handling. `normalize-item.ts`/`normalize-task.ts`/`normalize.ts` port `refreshData.js`'s item-slimming/PvE-merge/trader-price logic and `tarkovData.js`'s `adaptTask` item-requirement dedup - as pure, independently unit-tested functions, not legacy's DOM-coupled globals. `merge-with-previous.ts` ports the "don't let an API partial-outage nuke good cached data" per-section protection. `indexes.ts` ports the id/shortName/barter/craft reverse-index builders - built on demand by callers (e.g. via `useMemo`), never persisted (a `Map` silently serializes to `{}` under the cache persister). `use-tarkov-game-data.ts` is the public `useTarkovGameData()` React Query hook everything else consumes.
- `flea-market/` - `flea-tax.ts` ports `flea.js`'s `fleaTax`/`fleaNet` tax formula verbatim (including a small, deliberate fix to a count-flooring inconsistency between the two functions - see the file's doc comment). `item-predicates.ts` ports `isQuestTool` (used by `tarkov-api/normalize-task.ts` to exclude quest-tool items from a task's item requirements). Everything else in `flea.js` (`getMapValuables`, `renderValuables`, `fleaItemCardHtml`, etc.) is DOM/HTML-string UI code, explicitly out of scope here - that's Phase 4's valuables/kappa UI to rewrite clean.
- `item-resolution/` - `resolve-game-item.ts`/`find-item-location-entry.ts` port the shortName-key-then-substring-match resolution algorithm that both `beginnerItems.js` and `itemLocations.js` use to map their curated, non-tarkov.dev-id keys onto live item data (see `src/shared/data/README.md` for why those datasets don't store real ids). Joins static curated data with live item data, so it lives here rather than in `shared/data` (which stays a dependency-free leaf).

**Provenance notes** (what was intentionally left behind during porting): `refreshData.js`'s localStorage-cache-with-manual-24h-expiry is replaced by React Query + `@tanstack/react-query-persist-client` (see `src/app/providers.tsx`), not ported as code. `tarkovData.js`'s `adaptTask`/`adaptHideout` UI-shape renames, `MAP_ITEM_COUNTS`/valuables-map logic, and `ITEM_UNLOCKED_BY_TASK` are not ported - later feature phases' concern.
