Interactive map viewer, porting TarkovTrackerWB-main's Leaflet-based maps (quest markers, annotations, boss spawns, live clock, custom overlays), restyled with this project's design system. `old/tarkov-tips` contributes nothing here; its room-clearing rotation guides are excluded.

## Ported from

Rewritten clean using `react-leaflet` rather than re-wrapping vanilla Leaflet:

- `old/TarkovTrackerWB-main/src/components/maps/leaflet.js`: interactive map engine, the largest single port in the migration.
- `old/TarkovTrackerWB-main/src/lib/mapsConfig.js`: 13-map configuration and custom-map IndexedDB storage.
- `old/TarkovTrackerWB-main/src/lib/taskMarkers.js`: quest-marker overlay.
- `old/TarkovTrackerWB-main/src/components/maps/annotations.js`: freehand annotation/drawing tool.
- `old/TarkovTrackerWB-main/src/components/maps/mapHeader.js`: boss spawn-chance strip and live clock.
- `old/TarkovTrackerWB-main/src/components/maps/fullscreen.js`, `mapZoom.js`, `mapSidebar.js`, `sidebarFocus.js`: fullscreen/zoom/sidebar-focus behavior.
- `old/TarkovTrackerWB-main/src/components/maps/valuables.js`: high-value loot overlay.

## Status

Implemented and live at `/maps`, linked from the header nav and homepage feature grid. Map imagery (11 SVG plus 27 WebP, all 13 maps) ships under `public/maps/{svg,webp}/`; the SVGs are CC BY-NC-SA 4.0, noncommercial only. Ice Breaker has no published SVG overview, so its default view renders from a bundled tile pyramid instead, plus a 2D WebP variant.

## Boss gear and loot

Every portrait in the boss strip is a button that opens a card with that boss's gear and loot. The header shows the boss's spawn chance on the current map and total HP. Below it, gear is grouped by worn slot (weapons first, each with the rounds seen loaded in it), and loot is split into Common (10% or more), Uncommon (1% to 10%), and Rare (under 1%) bands, with a search box and a category filter. Rare starts collapsed since it's most of the list, but a search reaches into it, so typing "rusted" finds Kaban's 0.23% Rusted bloody key directly. Any row opens the app-wide item detail popup on top of the card.

The data comes from the `mobs` collection in tarkov.dev's `maps` payload, which the game-data proxy already fetched. It's compacted on the server in `src/shared/lib/tarkov-api/mob-loadouts.ts` (the raw form is several MB) into a top-level `mobs` section of the game data. Two things about it are easy to misread:

- **Loot chance is direct.** Each item's `prevalence` is the percentage of observed spawns that carried it.
- **Gear chance is derived.** Upstream's `equipment` is a plain list of everything seen across 15 sampled spawns per AI difficulty, with no probability attached, so the card counts how often each item appears and divides by the sample size. With 15 samples, each one is worth about 7%, which is why the card says "across 15 recorded spawns" instead of presenting the numbers as exact drop rates.

Faction pills (Black Division, AF, Rogues) combine their enemy types' data and say so. A few enemies have little or no data upstream, and the card shows an empty state for them.

## Collaborative sessions

A host can start a shared session and share a join code or invite link. While active, the host's map, pan, and zoom drive everyone's view, and a guest can request control. The drawing/annotation layer is shared and color-coded by author.

Built on [Liveblocks](https://liveblocks.io), the only real-time transport in this otherwise client-only app. Requires a `LIVEBLOCKS_SECRET_KEY` env var for the server routes under `src/app/api/maps-session/` that mint room tokens and end sessions; without it, hosting or joining a session fails. Set it in `.env.local` (gitignored):

```
LIVEBLOCKS_SECRET_KEY=sk_...
```

No client-side Liveblocks key is needed; the client authenticates through this app's own token route.
