## Not individually documented

- **Feature `README.md` files**, one per feature under `src/features/*`, recording status and legacy provenance. `tutorials`, `ballistics`, and `admin` are genuine stubs; `maps`, `pvp-guide`, `home`, and `external-resources` document already-shipped features. `home` and `external-resources` don't yet have their own per-file code-reference pages the way Progress Tracker does; that's a documentation gap, not a sign they're unfinished.
- **`src/types/README.md`**: records the colocation rule (types live with their one owning module). This folder is for genuinely cross-feature types and is deliberately empty so far.
- **Generated files**: `next-env.d.ts` content, `tsconfig.tsbuildinfo`, `package-lock.json`, Playwright reports. See [root configs](/docs/code-reference/root-configs).
- **Font binaries** (`src/app/fonts/**/*.otf|woff2`) and **ballistics JSON payloads** are data assets; their loaders and licensing are documented in [App](/docs/code-reference/app) and [Shared data](/docs/code-reference/shared-data).

## Maintenance

When a file is added, removed, or meaningfully changed, update its section in the area doc and this index in the same change. New sections follow the established template: Purpose, Walkthrough, Key decisions & constraints, Future work, with legacy provenance in the opening line and a brief entry for the test file immediately after.
